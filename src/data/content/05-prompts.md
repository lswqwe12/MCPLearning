Prompts（提示词）是 MCP 三大核心原语中的「模板」担当。本章讲解提示词的定义、控制权、核心特性、使用场景与三大原语的分工。

## 定义

提示词是引导语言模型交互的**预定义模板或指令**。MCP 为服务器向客户端暴露提示词模板提供了标准化方式。

与工具不同，提示词不执行任何外部操作，而是提供**可复用的交互脚本**——把「如何引导模型完成某类任务」沉淀成模板，供用户一键调用。

## 控制权：用户控制（User-controlled）

提示词是**用户控制**的——由用户选择调用的交互模板。

这意味着：

- 提示词不会像工具那样被模型「自动发现并调用」。
- 用户在界面上主动选择某个提示词模板，例如「代码审查」「生成周报」等。
- 用户还可以为模板提供参数（如待审查的代码片段），生成最终的提示词内容。

## 核心特性

- **客户端可以发现可用的提示词**：通过 `prompts/list` 获取模板列表。
- **客户端可以检索提示词内容**：通过 `prompts/get` 获取具体模板。
- **可以提供参数来自定义提示词**：模板支持占位符参数，调用时传入。
- **提示词可以包含结构化消息和指令**：内容可以是多条消息组成的结构。

## 提示词示例

一个「代码审查」提示词模板的定义：

```json
{
  "name": "code_review",
  "description": "Asks the LLM to analyze code quality and suggest improvements.",
  "messages": [
    {
      "content": "Please review the following code for quality, correctness, and potential improvements:\n\n{{.code}}"
    }
  ]
}
```

要点：

- `name`：模板标识。
- `description`：描述模板用途，方便用户选择。
- `messages`：结构化消息数组，构成提示词主体。
- `{{.code}}`：模板参数占位符，调用时由用户提供的真实代码替换。

## 使用场景

在设计一个 MCP Server 时，如何决定把某项能力暴露为哪种原语？核心判断标准是「它在做什么」：

- 将**数据**暴露为 **resource**（只读数据，如文档、记录）。
- 将**变更或计算操作**暴露为 **tool**（动作，如创建、更新、计算）。
- 将**可复用的多步骤工作流**暴露为 **prompt**（模板，如代码审查流程）。

## 三种原语的分工

| 原语 | 处理 | 控制权 | 类比 |
|------|------|--------|------|
| **Tools** | 动作（Action） | 模型控制 | 一支「能干活的手」 |
| **Resources** | 数据（Data） | 应用控制 | 一份「可查阅的资料」 |
| **Prompts** | 模板（Template） | 用户控制 | 一张「可套用的脚本」 |

> 记忆口诀：**Tools 做动作、Resources 供数据、Prompts 给模板。**

## 提示词模板集合

社区有大量预构建的 MCP 提示词模板，可用于各种 AI 驱动的工作流（代码审查、文档生成、数据分析等）。这些模板降低了「把最佳实践沉淀为可复用能力」的门槛。

## 本章小结

- Prompts 是**用户控制**的预定义模板，处理「模板」。
- 通过 `prompts/list` 发现、`prompts/get` 检索，支持参数化。
- 三大原语分工：**Tools=动作、Resources=数据、Prompts=模板**。
