本章讲解 MCP 的整体技术架构。理解「客户端-宿主-服务器」的分层设计、数据层与传输层的职责划分，以及背后的四条设计原则，是深入核心组件与通信机制的前提。

## 架构概览

MCP 遵循**客户端-宿主-服务器（Client-Host-Server）**架构，其中：

- 每个**宿主（Host）**可以运行**多个客户端（Client）**实例。
- 每个**客户端（Client）**与**一个服务器（Server）**保持 **1:1** 的有状态连接。
- 这种设计使用户能够在应用程序中集成 AI 功能，同时保持**清晰的安全边界**和**关注点隔离**。

```text
┌────────────────────────── Host（宿主，如 Claude Desktop）──────────────┐
│                                                                        │
│   ┌────────────┐   ┌────────────┐   ┌────────────┐                    │
│   │  Client 1  │   │  Client 2  │   │  Client 3  │   ← 每个客户端 1:1  │
│   └─────┬──────┘   └─────┬──────┘   └─────┬──────┘                     │
└─────────┼────────────────┼────────────────┼────────────────────────────┘
          │                │                │
          ▼                ▼                ▼
   ┌────────────┐   ┌────────────┐   ┌────────────┐
   │  Server A  │   │  Server B  │   │  Server C  │   ← 每个服务器独立
   │ (文件系统) │   │  (数据库)  │   │  (GitHub)  │
   └────────────┘   └────────────┘   └────────────┘
```

MCP 建立在 **JSON-RPC** 之上，提供**有状态会话协议**，专注于客户端和服务器之间的**上下文交换**与**采样协调**。

## MCP 的两层结构

MCP 在逻辑上分为两层：**数据层**负责「说什么」，**传输层**负责「怎么说」。这种分层让协议内容与通信载体解耦。

### 1. 数据层（Data Layer）

定义基于 JSON-RPC 的客户端-服务器通信协议，包括：

- **生命周期管理**：连接的初始化、能力协商、连接终止。
- **核心原语（Core Primitives）**：
  - `tools` —— AI 可调用的操作。
  - `resources` —— 提供给模型的上下文数据。
  - `prompts` —— 交互模板。
  - `notifications` —— 实时更新的通知机制。

### 2. 传输层（Transport Layer）

定义通信机制和通道，包括：

- **传输特定的连接建立**：如何建立连接。
- **消息帧（Message Framing）**：如何界定一条完整消息的边界。
- **授权认证**：如何校验通信双方的身份与权限。

> 分层的关键收益：同一个 MCP Server 的业务逻辑（数据层）可以跑在 STDIO、Streamable HTTP 等不同传输层之上，无需改动核心代码。

## 设计原则

MCP 的设计围绕四条核心原则展开，它们解释了「为什么协议长这样」。

### 1. 服务器应该极易构建

宿主应用处理复杂的编排职责，服务器聚焦于特定的、定义良好的能力。这意味着写一个 MCP Server 的门槛很低——你只需要实现具体的工具/资源/提示词，连接、协商、生命周期等复杂逻辑由协议和宿主承担。

### 2. 服务器应该高度可组合

每个服务器提供**隔离的**功能，多个服务器可以**无缝组合**。例如：一个文件系统 Server + 一个 GitHub Server + 一个数据库 Server，可以组合成一个能力丰富的 AI 助手，且互不干扰。

### 3. 服务器不能读取整个对话

服务器只接收**必要的上下文信息**，完整对话历史保留在**宿主端**。这一原则是**隐私与安全**的关键保障——外部服务器无法窥探用户的完整对话，只能拿到它完成任务所需的最小信息。

### 4. 功能可以渐进式添加

核心协议提供**最小必需功能**，额外能力可按需协商。这保证了协议的简洁与向后兼容，同时允许生态逐步扩展新能力（如 Tasks、MCP Apps 等扩展）。

## 本章小结

- MCP 采用**客户端-宿主-服务器**架构，客户端与服务器保持 1:1 连接。
- 协议分为**数据层**（JSON-RPC 通信协议）与**传输层**（通信机制）两层。
- 四条设计原则：**易构建、可组合、不读全对话、渐进式扩展**。
- 这些原则决定了后续所有组件与原语的设计取向。
