本章深入 MCP 架构中的三个核心参与者：**Host（宿主）**、**Client（客户端）**、**Server（服务器）**。理解它们各自的角色、职责与连接关系，是理解整个协议运行机制的关键。

## 参与者（Participants）

| 组件 | 角色 | 职责 |
|------|------|------|
| **MCP Host（宿主）** | AI 应用程序 | 协调和管理一个或多个 MCP 客户端 |
| **MCP Client（客户端）** | 连接器 | 维护与 MCP 服务器的连接，为宿主获取上下文 |
| **MCP Server（服务器）** | 服务提供者 | 向 MCP 客户端提供上下文的程序 |

这三者的关系可以类比为：

- **Host** 是「应用程序本身」（如 VS Code、Claude Desktop）。
- **Client** 是应用程序内部为每个服务器创建的「专属接线员」。
- **Server** 是外部「能力提供者」（如文件系统、数据库、GitHub）。

## 宿主的职责（Host）

宿主是整个集成场景的「大脑」与「管家」，负责：

- **创建并管理多个客户端实例**：根据用户配置连接多个服务器。
- **控制客户端连接权限和生命周期**：决定何时连接、何时断开。
- **执行安全策略和同意要求**：落实用户对数据访问的授权。
- **处理用户授权决策**：在工具执行前征得用户同意。
- **协调 AI/LLM 集成和采样**：组织模型调用与上下文注入。
- **管理跨客户端的上下文聚合**：把多个服务器的上下文整合给模型。

## 客户端的职责（Client）

客户端是宿主的「对外接口」，负责与具体服务器对接：

- **每个服务器建立一个有状态会话**：会话期间保持连接状态。
- **处理协议协商和能力交换**：与服务器协商支持的协议版本与能力。
- **双向路由协议消息**：在宿主与服务器之间转发消息。
- **管理订阅和通知**：处理服务器的实时更新。
- **维护服务器之间的安全边界**：不同服务器之间隔离，互不越界。
- **每个客户端与特定服务器保持 1:1 关系**：一个客户端只服务一个服务器。

## 服务器的职责（Server）

服务器是「能力提供者」，负责：

- **通过 MCP 原语暴露 resources、tools 和 prompts**：对外声明自己能提供什么。
- **独立运行，聚焦特定职责**：一个服务器做好一件事（如只负责文件访问）。
- **通过客户端接口请求采样**：在需要模型生成内容时反向请求宿主。
- **必须遵守安全约束**：只访问被授权的数据。
- **可以是本地进程或远程服务**：既能跑在本地子进程，也能是远端 HTTP 服务。

## 架构示意

根据官方文档的架构示意图，一个典型的运行态如下：

- **宿主进程内运行多个客户端**：一个宿主同时挂多个「接线员」。
- **每个客户端连接到不同的服务器**：互不干扰。
- **服务器可访问本地或远程资源**：服务器自身再去连接真实数据源。

```text
  └─────────────┘ └─────────────┘ └─────────────┘
```

## 示例：VS Code 作为 Host

当 VS Code 连接到 Sentry MCP Server 时，运行时实例化一个 MCP Client 对象来维护连接；当 VS Code 再连接到本地文件系统服务器时，会实例化**另一个** MCP Client 对象。

这个例子直观地说明了两点：

1. **一个 Host 管理多个 Client**。
2. **每个 Client 与一个 Server 一一对应**，连接之间彼此隔离。

## 本章小结

- **Host** 是协调者，管理客户端与安全策略。
- **Client** 是连接器，每个服务器对应一个专属客户端。
- **Server** 是能力提供者，通过原语暴露 tools/resources/prompts。
- 三者组合出「一个宿主 → 多个客户端 → 多个服务器」的清晰拓扑。
