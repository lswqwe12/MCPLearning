Resources（资源）是 MCP 三大核心原语中的「数据」担当。本章讲解资源的定义、控制权、核心特性、类型示例与代码实现。

## 定义

资源是为模型提供额外上下文的**结构化数据或内容**。

MCP 服务器是向 AI 应用暴露特定能力的程序，常见示例包括文件系统服务器、数据库服务器、GitHub 服务器等——它们对外暴露的核心，大多是「可供模型查阅的数据」，这些数据以资源的形式组织。

## 控制权：应用控制（Application-controlled）

资源是**应用控制**的——由客户端附加和管理的上下文数据。

与工具的「模型控制」、提示词的「用户控制」不同：

- 资源的**选择与附加**由应用（客户端）决定。
- 模型本身不会「自动调用」资源；而是应用把相关资源作为上下文注入给模型。
- 这保证了上下文注入的**可控性与确定性**。

## 核心特性

- **资源提供对信息的结构化访问**：数据以明确的结构暴露，而非原始字节流。
- **AI 应用可以检索资源并作为上下文提供给模型**：应用读取资源后注入模型上下文。
- **资源是只读的数据源**：资源用于「读」，不用于「写」；变更类操作应暴露为工具。

> 判断依据：需要让模型**读取数据** → 用资源；需要让模型**执行变更** → 用工具。

## 资源类型示例

| 服务器类型 | 暴露的资源 | 用途 |
|-----------|-----------|------|
| 文件系统服务器 | 文档 | 文档访问 |
| 数据库服务器 | 数据表/查询结果 | 数据查询 |
| GitHub 服务器 | 仓库/代码 | 代码管理 |
| Slack 服务器 | 频道/消息 | 团队通信 |
| 日历服务器 | 日程 | 日程安排 |

## 代码示例（Python - FastMCP）

使用 `@mcp.resource()` 装饰器暴露资源：

```python
from fastmcp import FastMCP

mcp = FastMCP(name="DataServer")

@mcp.resource("resource://greeting")
def get_greeting() -> str:
    return "Hello, World!"

@mcp.resource("data://config")
def get_config() -> str:
    return '{"theme": "dark"}'
```

要点：

- `@mcp.resource("resource://greeting")` 把函数注册为 URI 为 `resource://greeting` 的资源。
- 资源通过 **URI** 标识，客户端可通过 URI 检索内容。
- 返回值为字符串（也可以是更丰富的结构），作为注入模型的上下文。

## 本章小结

- Resources 是**应用控制**的结构化只读数据，处理「数据」。
- 资源通过 URI 标识，由应用检索并注入模型上下文。
- 与工具、提示词的分工：**资源供数据、工具做动作、提示词给模板**。
